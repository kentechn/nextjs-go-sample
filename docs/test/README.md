# テストドキュメント

## どのドキュメントをどの単位で作るか

| ドキュメント | 単位 | 答えること | 寿命 |
| --- | --- | --- | --- |
| 仕様書 | 機能 / ドメイン | 何が正しい振る舞いか | 長い（実装と同期） |
| テスト方針（既存） | リポジトリ | どの層を何でテストするか | 長い |
| テスト計画書 | 案件・リリース | 何を・どこまで・いつ・誰が検証するか | 案件終了まで |
| テスト設計書 | 機能 / API 単位 | どの観点でどのケースを流すか | 機能が続く限り |

## 使い分けの目安

- 小さい変更（PR 1 本）: 仕様書の該当節を更新 + テスト設計書にケースを追記。計画書は作らない。
- 新機能 / リリース単位: 3 点セットを作る。
- 定常ルール（層ごとのツール選定、CI ジョブ対応）は `docs/testing-policy.md` に置いて、計画書からは参照だけする。
- 自動化するテストと手動確認は設計書の同じ表で管理し、手動は理由を書く（書けないものは自動化する）。
