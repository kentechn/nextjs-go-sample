## 1. 目的

## 2. 対象
- 対象機能 / 変更範囲（PR・仕様書へのリンク）
- 影響範囲（回帰確認が必要な既存機能）

## 3. テストレベルとタイプ
| レベル | 目的 | ツール | 担当 | 判断基準 |
| --- | --- | --- | --- | --- |
| ユニット（domain / usecase） | 業務ルールの回帰 | go test + testify | 実装者 | 追加ロジックに正常系1+異常系1 |
| 結合（presentation） | HTTP 契約・エラー形 | httptest（ルータ全体） | 実装者 | operation ごとに 1 本以上 |
| フロントユニット | Zod 境界値 / 変換ロジック | Vitest | 実装者 | - |
| コンポーネント | 状態列挙 + 操作 | Storybook（play + a11y） | 実装者 | 追加コンポーネントに story 1 本 |
| E2E | 主要フロー疎通 | Playwright | 実装者 | golden path + 主要失敗系 |
| 静的検査 | 仕様と生成物の同期 | `task gen:check` / `docs:lint` | CI | - |

方針の詳細は `docs/testing-policy.md` を参照（ここでは案件固有の差分だけ書く）。

## 5. テストデータ方針
- 一意化の方法（`Date.now()` 等）、共有状態を持たない、時刻/ID は固定値を注入。

## 6. 開始条件 / 完了条件
- 開始: 仕様書レビュー済み、OpenAPI 更新済み、`task gen` 実行済み。
- 完了: CI 全ジョブ green / 未解決の Critical・High が 0 / 設計書のケースが全て実行済み。
